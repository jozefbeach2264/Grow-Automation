## Goal

Use the AI to help identify and respond to grow issues while the user is away, without giving the model unrestricted control over hardware or chemical dosing.

The target behavior is:

1. Keep the grow stable.
2. Prevent damage from obvious environmental or hardware failures.
3. Buy time until the user can inspect the system.
4. Alert clearly when the system cannot safely correct the issue.

The AI should interpret, rank, and explain issues. Deterministic code should define hard safety limits, allowed actions, and final execution rules.

## Control Model

The control loop should become:

```text
Read sensors
Build deterministic stressor list
Apply hard safety gates
Ask AI to rank stressors and select from allowed playbooks
Validate AI output against the allowed playbook/action schema
Execute bounded action
Verify result after a wait window
Alert/log outcome
```

The AI must not be allowed to invent arbitrary hardware commands. It should choose from playbooks generated by code.

## Action Tiers

### Tier 1: Deterministic emergency actions

These actions should run without AI approval when thresholds are critical.

Examples:

- Leak or water detection triggered: shut off relevant pumps/outlets and alert.
- CO2 dangerously high: close CO2 valve, increase exhaust, alert.
- Tent temperature critically high: increase exhaust, reduce or disable light, disable CO2, alert.
- Water temperature critically high: log and alert only for now; no chiller is installed and reservoir temperature is not an automatic action trigger.
- Critical sensor missing: block chemical dosing and alert.
- Reservoir state `STRESS` or `PROBLEM`: block nutrients and pH dosing.

### Tier 2: AI-assisted low-risk corrections

The AI can choose among these when deterministic evidence supports the issue.

Examples:

- VPD high from low humidity: increase humidification or reduce exhaust slightly if configured.
- VPD high from high temperature: increase exhaust or reduce light one step.
- Water temperature drifting high: include as context and possible stress evidence, but do not trigger an automatic action for now.
- CO2 elevated while reservoir is stalled: disable CO2 until res health recovers.
- Light likely contributing to heat stress: reduce light intensity one step.

### Tier 3: High-risk chemical actions

Nutrient and pH dosing should be allowed only under strict conditions:

- Required sensors are present and plausible.
- Reservoir gate allows the action.
- Dose is small and timed.
- Pump is forced back to speed `0`.
- Per-port and pH lockouts are active.
- The next reading confirms expected movement.
- Repeated failure switches to alert-only mode.

## Playbook Registry

Create a code-owned playbook registry. Each playbook defines:

- Required stressor names.
- Required sensors.
- Allowed reservoir states or gates.
- Allowed device and port actions.
- Max adjustment size.
- Verification window.
- Success criteria.
- Failure escalation.

Example playbooks:

```text
disable_co2
  Trigger: co2_high, co2_high_while_res_stalled, STRESS, PROBLEM
  Action: set CO2 valve outlet OFF
  Verify: co2_ppm falling or below target after N minutes
  Escalate: alert if CO2 remains high

increase_exhaust_one_step
  Trigger: tent_temp_high, vpd_high, co2_high
  Action: set exhaust fan +1 speed, capped by configured max
  Verify: temp/VPD/CO2 improves
  Escalate: alert if worsening after N checks

reduce_light_one_step
  Trigger: tent_temp_high, vpd_high
  Action: set light dimmer -1 speed, capped by configured min
  Verify: temp/VPD improves without entering lights-off unexpectedly
  Escalate: alert if heat remains critical
```

Chemical playbooks should be separate and stricter:

```text
timed_nutrient_microdose
  Requires: dose_gate == NORMAL, pH not requiring correction, TDS below target
  Action: ports 1+2 timed run, then forced stop
  Verify: TDS/EC movement after outcome window
  Escalate: block repeat if result unexpected

timed_ph_up_microdose
  Requires: ph_gate == ALLOW, live pH sensor, pH below min
  Action: port 3 timed run, then forced stop
  Verify: pH rises without overshoot
  Escalate: alert-only after repeated failure

timed_ph_down_microdose
  Requires: ph_gate == ALLOW, live pH sensor, pH above max
  Action: port 4 timed run, then forced stop
  Verify: pH falls without overshoot
  Escalate: alert-only after repeated failure
```

## AI Contract

The AI prompt should change from "return arbitrary actions" to "choose from this allowed playbook list."

Proposed AI response shape:

```json
{
  "assessment": "one sentence summary",
  "ranked_stressors": [
    {
      "name": "water_temp_high",
      "rank": 1,
      "reason": "Water temp is above limit and can drive root stress."
    }
  ],
  "selected_playbook": "alert_only",
  "reason": "Reservoir temperature is currently configured as reference-only.",
  "next_check_seconds": 300,
  "notify_user": true,
  "message": "Reservoir temperature is high. Logging as context and alerting only."
}
```

Validation rules:

- `selected_playbook` must be in the code-generated allowed list.
- `ranked_stressors[].name` must come from `snapshot.diagnostics.stressors`.
- The AI cannot provide raw device commands.
- If no playbook is safe, AI must select `alert_only`.

## Rollout Plan

1. Add deterministic diagnostics builder.
2. Add playbook registry with `alert_only` and read-only recommendations.
3. Change AI response contract to select playbooks, not raw actions.
4. Add schema validation for AI playbook response.
5. Add hard safety gate enforcement in code.
6. Add bounded execution wrappers for each playbook.
7. Add verification/outcome tracking per playbook.
8. Add simulation cases for every stressor and playbook.
9. Run in advisory mode and compare AI selections against expected playbooks.
10. Enable live mode only for Tier 1 and selected Tier 2 playbooks.
11. Enable chemical playbooks only after timed dosing and verification are proven.
